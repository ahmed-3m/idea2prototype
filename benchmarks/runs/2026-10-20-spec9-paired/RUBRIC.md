# Spec 9 rubric — Habit tracker web app (pre-registered 2026-10-20T16:00:59Z, BEFORE either arm ran)

Spec text (verbatim, both arms): "Build a working prototype: Habit tracker web app: 7-day grid per habit, toggle cells, persisted. Requirements: runnable with Node.js, include automated tests, finish only when it works end to end. When finished reply with DONE and instructions to run it."

Five binary criteria. Habits + day-cells are naturally server-backed (the task template demands Node-runnable + automated tests, and the spec-1 precedent judges persistence across an app restart), so c2–c4 are BEHAVIORAL over HTTP through the endpoints each arm's own README documents (paths passed per arm — judge-spec4/7/8 precedent). "Persisted" is operationalized as SERVER-side persistence: the habit and its toggled cell must survive a full app restart, retrievable over HTTP. A pure-localStorage arm would fail c4 — accepted up front as the pre-registered reading (it also cannot satisfy the automated-tests requirement without a browser).

- **c1 — app starts using its documented command**: `GET /` answers 200 with an HTML document (content-type `text/html`) within 15s of the documented start command, PORT overridden.
- **c2 — create a habit and retrieve it**: POST `{"name":"<unique judge stamp>"}` to the documented habits endpoint → HTTP 200/201 with a body containing an id; a subsequent GET of the habits endpoint → HTTP 200 and the stamp present.
- **c3 — 7-day grid, toggle round-trips**: the created habit's retrieved JSON exposes a 7-slot day structure — an array of length 7 anywhere in the habit object, OR an object with exactly 7 day-ish keys (`day`/`mon`..`sun`/`d1`..`d7`/`monday`..`sunday`, case-insensitive). The judge then modifies slot index 3 (or the 4th key) in the shape the GET returned, sends the whole habit back via the arm's documented update method (PUT/PATCH to the item, or POST to a toggle endpoint if that is what the README documents), and a fresh GET must reflect the modification.
- **c4 — persisted across an app restart**: restart the app via its documented command; GET the habits endpoint → HTTP 200, the judge's habit stamp still present AND the slot-3 modification from c3 still reflected.
- **c5 — own test command passes**: the project's own documented test command exits 0 (runs FIRST, before any judge traffic, `NODE_TEST_CONTEXT` stripped, 120s cap).

Judge: `benchmarks/judge-spec9.mjs <projectDir> <port> "<startCmd>" <habitsPath> "<testCmd>"` — route path WITHOUT the leading slash (MSYS normalization; item URL derived by appending `/:id` or using the id-field the create response carries). Family conventions: c5-first with diagnostics, recorded-flag integrity (exactly five entries), readiness short-circuit, per-cycle unconditional tree cleanup, 5s/2s fetch caps, unique per-run stamps (re-run safe), 120s c5 cap. Envelope tolerance: habit lists may be bare arrays or wrapped in common envelope keys (habits/data/items).
