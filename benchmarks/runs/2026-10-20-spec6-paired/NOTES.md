## Deviations from protocol (documented honestly)

1. **Builder was the orchestrator session, not fresh subagent sessions** — Agent tool broken 4+ consecutive days. In-session sequential builds preserve the within-subject pairing but weaken the fresh-session control; the control arm benefited from a warmed builder this time (its harness reused lessons the fresh protocol would have re-learned the hard way — the spec-5 control's fix cycles, ~7m28s, show what the un-warmed version costs).
2. **Token usage not recorded** — RQ1 untested.
3. **Functional judge knew the arms** — mitigations: rubric pre-registered with timestamp before builds, criteria executed mechanically, verifier arm-blind.
4. **Machine not perfectly idle**; wall-clock from unix timestamps (14:28:55→14:30:44, 14:30:59→14:35:43 UTC).
5. No persistent store in either arm, so the judge-re-runs-poison-stores hazard did not apply (c5-first discipline kept anyway).
6. **One transient c5 observation, re-run clean:** the control's first judge run failed c5 (`npm test` non-zero inside the judge's spawn; passed standalone before and after, and on judge re-run 5/5). No cause was captured for the original blip (likely a port/TIME_WAIT race on the default port the control's test binds). The archived judge carries the full round-2 family hardening (driven by the spec-5 PR's external review, folded in BEFORE this run was archived): c5 capped at 120s with output-tail diagnostics on failure (a hung test command fails c5 instead of hanging the judge — exactly this run's transient class), every fetch capped at 5s, unconditional process-tree cleanup, and an origin-based per-asset collector (RFC 9239 MIME included). Recorded verdicts with that judge: control 5/5, treatment 4/5 — identical to the pre-hardening judgments.
7. **c2's served-source scope, published as-is:** the treatment's server-side durations are invisible to the pre-registered collector; no post-hoc widening after an arm-correlated failure (see results). The rubric's pre-registered limitation ("source-presence cannot prove a ticking timer; applies identically to both arms") covers exactly this class.
8. Timer flows probed live on both arms: treatment (start 2s work → break, cycles 1, 29s remaining → reset) and control (page + /timer.mjs served with UI markup).
