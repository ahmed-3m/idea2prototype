## Deviations from protocol (documented honestly)

1. **Builder was the orchestrator session, not fresh subagent sessions** — Agent tool broken 4+ consecutive days ("No reasoning level selected"). In-session sequential builds preserve the within-subject pairing but weaken the fresh-session control; wall-clock includes orchestrator tool latencies, so both arms' times are upper bounds inflated by the same builder.
2. **Token usage not recorded** — RQ1 untested.
3. **Functional judge knew the arms** — mitigations: rubric pre-registered with timestamp before builds, criteria executed mechanically, verifier arm-blind.
4. **Machine not perfectly idle**; wall-clock from unix timestamps (14:07:11→14:11:19, 14:11:53→14:19:21 UTC), rounded honestly.
5. No persistent store in either arm, so the judge-re-runs-poison-stores hazard did not apply (c5-first discipline kept anyway).
6. **UI criteria are source-presence predicates, pre-registered up front** — a zero-dependency blind judge cannot drive a browser, so c2–c4 check the served source (fetching the app's own HTML/scripts/API payloads) instead of rendered behavior. A broken score line could pass c3; this weakness applies identically to both arms.
7. **The judge's source collector was hardened in TWO rounds, both arms re-judged identically after each (final verdicts 5/5 = 5/5, unchanged throughout; original strict results preserved here: both arms 4/5, c2 FAIL ×2).** The pre-registered collector (root HTML + `<script src>` assets) missed both natural quiz shapes: the treatment's questions arrive as JSON from `GET /api/quiz`, the control's live in a module reached by an inline `import '/grade.mjs'`. Both apps demonstrably present 5 questions in the browser — the collection was the defect, not the apps. **Round 1** (post-results, spec-4/7 precedent): follow `<script src>` attributes, static import specifiers, and first-arg `fetch('…')` literals (GET; POST-only endpoints answer 405/404 and are skipped), bounded to 3 rounds / 20 assets. **Round 2** (external review of the results PR — CodeRabbit 9 findings + opencode nits, both reviewers converged): origin-based reference filtering (resolve every reference, keep it only if it lands on the judge's origin — admits root-absolute/relative/bare-relative/same-origin-protocol-relative, excludes CDNs and bare specifiers), per-asset-relative resolution (a `./x.mjs` inside `/js/main.mjs` resolves against the asset, not the site root), `application/javascript` accepted (RFC 9239), every fetch capped at 5s (an SSE stream can no longer hang the judge), the c5 test command capped at 120s (a hung test command fails c5 instead of hanging the judge), unconditional process-tree cleanup (a shell that exits while a backgrounded server lives no longer skips the kill), and c3's `.length` alternative constrained to a score/template context per the frozen rubric wording. Criteria text unchanged; predicates only tightened toward the rubric's own words. **Executed-script provenance:** pre-hardening and round-1 runs used the `D:/tmp/i2p-spec5/` twin; round 2 + the final recorded re-judgment used THIS archived `benchmarks/judge-spec5.mjs` — the copy of record. Process lesson recorded for future rubric authors: enumerate content-delivery shapes (inline / script-src / module-import / API-JSON) BEFORE pre-registering a served-source criterion.
8. Judge traffic and quiz flow probed live: treatment `POST /api/quiz` all-correct → `{score:5,total:5}`; control page + `/grade.mjs` served 200 with quiz UI markup.
