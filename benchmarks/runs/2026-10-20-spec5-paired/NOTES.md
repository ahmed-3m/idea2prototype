## Deviations from protocol (documented honestly)

1. **Builder was the orchestrator session, not fresh subagent sessions** — Agent tool broken 4+ consecutive days ("No reasoning level selected"). In-session sequential builds preserve the within-subject pairing but weaken the fresh-session control; wall-clock includes orchestrator tool latencies, so both arms' times are upper bounds inflated by the same builder.
2. **Token usage not recorded** — RQ1 untested.
3. **Functional judge knew the arms** — mitigations: rubric pre-registered with timestamp before builds, criteria executed mechanically, verifier arm-blind.
4. **Machine not perfectly idle**; wall-clock from unix timestamps (14:07:11→14:11:19, 14:11:53→14:19:21 UTC), rounded honestly.
5. No persistent store in either arm, so the judge-re-runs-poison-stores hazard did not apply (c5-first discipline kept anyway).
6. **UI criteria are source-presence predicates, pre-registered up front** — a zero-dependency blind judge cannot drive a browser, so c2–c4 check the served source (fetching the app's own HTML/scripts/API payloads) instead of rendered behavior. A broken score line could pass c3; this weakness applies identically to both arms.
7. **The judge's source collector was hardened AFTER both arms scored 4/5, then both arms were re-judged (5/5 unchanged for c1/c3/c4/c5, c2 4→5 on BOTH arms identically).** The pre-registered collector (root HTML + `<script src>` assets) missed both natural quiz shapes: the treatment's questions arrive as JSON from `GET /api/quiz`, the control's live in a module reached by an inline `import '/grade.mjs'`. Both apps demonstrably present 5 questions in the browser — the collection was the defect, not the apps. Hardened per the spec-4/7 precedent: the collector now follows, mechanically and same-origin only, `<script src>` attributes, static import specifiers, and first-arg `fetch('…')` literals (GET; POST-only endpoints answer 405/404 and are skipped), bounded to 3 rounds / 20 assets. Criteria text and predicates unchanged; original strict-collector results preserved here (both arms 4/5, c2 FAIL ×2). Process lesson recorded for future rubric authors: enumerate content-delivery shapes (inline / script-src / module-import / API-JSON) BEFORE pre-registering a served-source criterion. **Executed-script provenance (external-review finding):** the pre-hardening and immediate post-hardening runs used the `D:/tmp/i2p-spec5/` twin; after a thermo-review fix (protocol-relative `//` exclusion — no arm references any `//` URL, so the difference is provably nil for these arms) both arms were re-judged from THIS archived `benchmarks/judge-spec5.mjs` copy → 5/5 unchanged; it is the copy of record. **Known latent collector gaps, external-review nits, all conservative-direction (under-collect → c2 fail, never false-pass), nil for these arms, queued for the next judge-family hardening:** bare-relative refs (`src="app.js"`, `fetch('api/quiz')`) excluded; `application/javascript` content-type skipped; `./` specifiers inside non-root assets resolve against site root, not the referring asset; collector fetches have no timeout (a same-origin SSE stream would hang the judge); c3 implements the rubric's "`.length` in a score/template context" as context-free `\.length` — looser than the frozen wording, non-load-bearing here (both arms pass c3 via `total` + `${score} / ${total}` evidence).
8. Judge traffic and quiz flow probed live: treatment `POST /api/quiz` all-correct → `{score:5,total:5}`; control page + `/grade.mjs` served 200 with quiz UI markup.
