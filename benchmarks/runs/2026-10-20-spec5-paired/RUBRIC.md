# Spec 5 rubric — Quiz web app (pre-registered 2026-10-20T14:06:45Z, BEFORE either arm ran)

Spec text (verbatim, both arms): "Build a working prototype: Quiz web app: 5 hard-coded questions, score at the end, restart button. Requirements: runnable with Node.js, include automated tests, finish only when it works end to end. When finished reply with DONE and instructions to run it."

Five binary criteria. Because a quiz web app is UI-centric and may legitimately have NO HTTP protocol for answers/scoring (pure client-side logic is a valid reading of the spec), criteria c2–c4 are operationalized at the SERVED-SOURCE level — the judge fetches the app's HTML over HTTP plus every same-origin `<script src>` asset it references and analyzes the combined source. This operationalization is part of the pre-registration: it is blind (script never sees which arm produced the project), mechanical (regex/count predicates, no judgment calls), and applied identically to both arms. Known limitation, accepted up front: source-presence is weaker than behavior for UI criteria — a broken score line could pass c3; this is the honest cost of a zero-dependency judge and applies equally to both arms.

- **c1 — app starts using its documented command**: `GET /` answers 200 with an HTML document (content-type `text/html`), within 15s of the documented start command with PORT overridden.
- **c2 — five hard-coded questions**: the combined served source (root HTML + same-origin script assets) contains ≥5 DISTINCT question strings. A question string = a quoted literal (`'…'`, `"…"`, backtick, or JSON string value) of ≥10 characters containing `?` and at least 3 letters.
- **c3 — score at the end**: combined source contains a score identifier (`score`, case-insensitive) AND a score-relative-to-total presentation (any of: `out of`, `X / 5`-style division by the question count, `.length` in a score/template context, `total`, `percent`). Both regexes must match.
- **c4 — restart button**: combined source contains a restart control (`restart|play again|try again|retry|reset|start over|again`, case-insensitive) AND quiz-state reset logic (`location.reload` OR an assignment returning a counter/store to its initial value: `score…= 0`, `index/current/i = 0`, `answers = []`, or equivalent DOM clear). Both regexes must match.
- **c5 — own test command passes**: the project's own documented test command exits 0 (run FIRST, before any judge traffic, so judge writes cannot poison fixtures; `NODE_TEST_CONTEXT` stripped from the spawned env).

Judge: `benchmarks/judge-spec5.mjs <projectDir> <port> "<startCmd>" "<testCmd>"` — conventions mirror judge-spec4/7 (recorded-flags integrity so exactly five entries are always reported; readiness short-circuit; whole-tree kill on Windows `taskkill /T`, POSIX detached group with ESRCH guard; route-free — no API paths assumed).
